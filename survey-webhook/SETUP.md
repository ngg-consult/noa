# חיבור SurveyLegend ל-Google Sheets עם התראה על תשובה שלילית

## שלב א – הקמת הגיליון והסקריפט
1. לפתוח Google Sheet חדש (למשל "תוצאות סקר נוסעים").
2. בתפריט: **Extensions → Apps Script**.
3. למחוק את התוכן הקיים ולהדביק את כל התוכן של `Code.gs`.
4. בראש הקובץ, בתוך `CONFIG`:
   - `SECRET_KEY` – להחליף למחרוזת אקראית (אותיות ומספרים בלבד, לפחות 20 תווים).
   - `ALERT_EMAILS` – לשים בשלב הניסיון את המייל שלך בלבד.
   - `SURVEY_NAME` – שם הסקר.
5. לשמור (Ctrl+S).

## שלב ב – בדיקה פנימית
1. לבחור בסרגל העליון את הפונקציה `testWebhook` וללחוץ **Run**.
2. Google תבקש הרשאות (גישה לגיליון ושליחת מייל) – לאשר.
3. לבדוק שנוצרו בגיליון הלשוניות **Raw** ו-**Responses** עם שורת ניסיון.

## שלב ג – פרסום כתובת ה-Webhook
1. **Deploy → New deployment** → סוג: **Web app**.
2. Execute as: **Me**. Who has access: **Anyone**.
3. ללחוץ **Deploy** ולהעתיק את ה-URL (מסתיים ב-`/exec`).
4. להוסיף לסוף הכתובת: `?key=` ואחריו ה-SECRET_KEY שהגדרת.

## שלב ד – הגדרה ב-SurveyLegend
| שדה | ערך |
|---|---|
| Endpoint URL | הכתובת משלב ג כולל `?key=...` |
| Trigger on | Submitted |
| Data format | JSON |
| Append responses | כבוי |

לשמור, ללחוץ **Test**, ואז למלא את סקר הניסיון פעם אחת עד הסוף.

## שלב ה – הגדרת "תשובה שלילית"
אחרי שתשובה אמיתית נכנסה ללשונית **Responses**, לפי שמות העמודות ממלאים את `NEGATIVE_RULES` בסקריפט.

**חשוב:** כל שינוי בקוד מחייב **Deploy → Manage deployments → Edit → Version: New version**.
אחרת הכתובת ממשיכה להריץ את הגרסה הקודמת.

## הערות
- הכתובת והמפתח רגישים – לא לשתף מחוץ לצוות.
- Google מגבילה את מספר המיילים היומי שסקריפט יכול לשלוח. יש לבדוק את המגבלה העדכנית בתיעוד של Google (Apps Script Quotas).
- הדאשבורד ייבנה ב-Looker Studio על בסיס הלשונית Responses, אחרי שמבנה הנתונים יתברר.
